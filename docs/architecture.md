# JARVIS-X Architecture

## System loop

PERCEIVE → STATE → CLASSIFY → SCOUT → DECOMPOSE → PLAN → ROUTE → ACT/RESEARCH → VERIFY → CHALLENGE → ADAPT → LEARN → RETEST

## Organism model

Models are organs. JARVIS-X is the organism.

- Executive reasoning: orchestrates the task and synthesizes results.
- Critic/red team: attacks assumptions, contradictions, and weak evidence.
- Coding organ: implements changes and tests.
- Research organs: gather current and domain-specific evidence.
- Multimodal organs: inspect visual/audio inputs when required.
- Memory organs: persist decisions, context, lessons, and evidence.
- External tools: provide capabilities such as GitHub, browser automation, data access, and deployment.

## Capability lifecycle

AVAILABLE ≠ INVOKED ≠ EXECUTED ≠ CORRECT ≠ COMPLETED ≠ WORLD-STATE VERIFIED

Every material capability is tracked through those states.

## Routing

Routing is outcome-driven. A capability remains preferred only when evaluation evidence shows that it improves the target outcome under comparable conditions.

## Verification

Material work follows BASELINE → INTERVENTION → COMPARABLE RETEST → MEASURE → KEEP / MODIFY / REJECT / UNPROVEN.
