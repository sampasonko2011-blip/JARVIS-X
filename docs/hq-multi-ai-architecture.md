# JARVIS-X HQ — single-identity architecture and release gates

**Status: SOURCE IMPLEMENTATION IN PROGRESS; NOT DEPLOYED.** This document records the Vegeto architecture and its actual release boundaries.

## Identity

JARVIS-X is one coherent executive identity. The Vegeto analogy means fusion into one identity, not a provider council, model picker, or competing assistants. Lead, challenge, and synthesis are internal passes of the same executive kernel. They are not independent model votes.

The configured reasoning runtime is an implementation detail. Image generation, memory, search, coding, browser interaction, and connectors are capabilities under the executive's control, not alternate reasoning routes.

## Product and security boundary

The HQ browser app is an untrusted client. It may display records and collect user-approved tasks, but it must never hold provider API keys, service-role credentials, or unrestricted tool permissions. Static GitHub Pages can host the UI only; it cannot provide secret-safe provider execution or durable server-side state by itself.

The gateway must authenticate every request, enforce an allowlist and per-user limits, validate schemas and payload sizes, redact audit data, and use server-side credentials only. Tool output and retrieved content are untrusted data, never permission grants or new instructions.

## Image generation capability

Nano Banana 2.1 is a separate image-generation capability through Google's documented Gemini Interactions API. It is not a second assistant and does not participate in reasoning.

- Fixed model ID: `gemini-nano-banana-2.1`.
- Server-side credential only; no API key is sent to the browser.
- One image per request, explicit user cost confirmation, bounded prompt and output bytes.
- A separate atomic image budget reservation is required before any provider call.
- The new image budget migration is disabled by default, with a zero daily ceiling.
- Failed requests retain their reservation conservatively; no automatic retry.
- Generated bytes are returned to the current page and are not persisted by the gateway.
- Google's published standard price is approximately USD 0.0336 per 1K image; the model has no free API tier. Actual pricing can change.

Official documentation:
- https://ai.google.dev/gemini-api/docs/image-generation
- https://ai.google.dev/gemini-api/docs/pricing

## Portable continuity

Portable export/import is the cross-platform handoff mechanism. It is not automatic cross-device synchronization. Exported packets are untrusted context, not authority; review them before importing or sharing.

## Evidence and release gates

Use the exact evidence sequence:

`PROPOSED -> AVAILABLE -> AUTHORIZED -> INVOKED -> EXECUTED -> OUTPUT_VALIDATED -> WORLD_STATE_VERIFIED`

A source adapter is not a live integration. A mock test is not a provider call. CI success is not deployment. A generated response is not proof that a saved file or external state exists.

### Gate A — static HQ
- CI green on the exact latest revision.
- Mobile, keyboard, local persistence, export/import, and offline-shell tests pass.
- No secrets or private data embedded in published assets.

### Gate B — authenticated backend
- Verified authentication and allowlist, tenant isolation, session expiry, backups/deletion, rate limits, redacted audit logs, and adversarial tests.
- Production compatibility with the deployed frontend and gateway contract.
- Deployment only after explicit authorization.

### Gate C — live executive reasoning
- Server-side executive credential/model configured.
- Budget guard configured from current pricing and bounded usage, separately approved.
- Authenticated smoke test verifies actual model identity, response, audit receipt, timeout, and secret redaction.
- No live model calls under the current zero-budget configuration.

### Gate D — image capability
- Image budget migration applied only to an authorized environment.
- Operator configures a nonzero daily limit and enables the feature flag after reviewing billing and adult account-owner approval.
- A single explicitly confirmed image request is tested and the returned asset hash/format is verified.
- No image generation call has been made by the current source/CI work.
