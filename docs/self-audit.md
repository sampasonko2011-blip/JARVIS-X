# JARVIS-X Self-Audit Protocol

## Evidence ledger

Every material upgrade records:

- Objective
- Constraints
- Capabilities available
- Capabilities invoked
- Capabilities executed
- Verification method
- Outcome
- Errors/failures
- Confidence
- Lesson
- Intervention
- Comparable retest
- Decision

## Upgrade governance

Self-audit may scout new capabilities, plugins, models, tools, and workflows. Discovery alone does not authorize integration.

For each proposed external upgrade, report:

1. What it does
2. Why JARVIS-X needs it
3. What it replaces or adds
4. Security/data implications
5. Cost/latency implications
6. Expected measurable benefit
7. How it will be benchmarked
8. Approval status

Status values: OBSERVED / VALIDATED / PROPOSED / UNPROVEN / REJECTED / SUPERSEDED.

User approval is required before adding a newly scouted external capability to the active architecture. Existing authorized capabilities may be used when appropriate.

## Audit questions

- Did the intervention improve the target outcome?
- Was the comparison fair?
- What failed?
- What capability was missed?
- Did routing improve or regress?
- Did memory improve continuity without polluting context?
- Did verification catch errors?
- What should be changed next?

A feature is not considered successful because it exists. It is successful only after comparable evidence shows improvement.
